# 101 通道识牌监控

101 的 `carpointcloud-plate-watch.service` 每 5 秒读取现场 DM8。从 2026-11-26 10:32:19 上线时刻起，登记 CH2、CH3、CH4 的自动来车及车牌匹配结果。查看界面关闭后服务继续运行。

在 101 使用现场账号执行以下命令。

```sh
# 三个通道的已匹配、未匹配和待定车次总数，以及最后一次成功同步时间
/data/carpointcloud/ops/plate-watch/plate-watch --status

# 先看最近 20 辆，再持续显示三个通道的新车和状态变化
/data/carpointcloud/ops/plate-watch/plate-watch --follow

# 只看 CH4 最近 50 辆并继续跟踪
/data/carpointcloud/ops/plate-watch/plate-watch --channel CH4 --limit 50 --follow

systemctl is-active carpointcloud-plate-watch.service
systemctl is-enabled carpointcloud-plate-watch.service
```

界面按车次显示来车通道、到磅时间、状态、已确认车牌、尝试次数、乙方抓拍时间和 enterID、我方首次看到该抓拍的时间、识牌任务决定时间与耗时。成功车牌以 DM8 已绑定事实为准。多条抓拍均有可能属于前车时，现场通常看到失败状态和“未找到可唯一归属本车的抓拍”。要核对某车每次交互中的所有候选及排除理由，可用界面末尾的 workflow 查询已有现场业务日志：

```sh
grep -F -- 'workflowId=<本车workflow>' /data/carpointcloud/logs/webapi/service.log
```

独立缓存位于 `/data/carpointcloud/service-state/plate-watch/monitor.sqlite`。私有目录权限 0700，数据文件权限 0600。缓存保留最近 30 天的车次和轮询观察到的状态变化，每小时从 DM8 校核一次保留期内数据。重启或短时失联后，未收口车次继续跟进，终态车次按 workflow 去重。同步中断时 `--status` 的最后同步时间会停止前进。更早的业务事实按系统原有保留策略查询 DM8。候选车牌及实际业务日志均在内网服务器查看。
